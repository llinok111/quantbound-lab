# quantbound-lab

**承诺（含数字与对照基线）：** 在 **16,017 顶点 / 31,360 三角**的波纹薄带网格上，本工具给出**精确最坏量化误差 + 见证顶点**：
位置 **12 bit** 相对 bbox 对角线误差 **1.2210e-4**（逐轴 halfStep 解析上界 1.2957e-4；独立 oracle 在 5 个位深上逐位一致，最大相对差 3.5e-14）；
同一 **16 bit 总预算**下，八面体法向编码平均角误差 **0.2728°**、最坏 **0.6425°**，而逐分量 15 bit 基线是 **1.4219° / 2.9513°**（**5.21× / 4.59×** 更小）；
容差 1e-3（相对）下位置最小位深 **9 bit**，并给出 **8 bit 必失败**的见证顶点（1.961e-3 > 1e-3，v8008）。
所有数字来自 `bench/result.json` 与 `node bench/verify.mjs` 的真实运行（12/12 断言）。

Upstream: none

这是一个原创工具，不 fork、不包装任何仓库；`src/core.mjs` 为纯 ES module（不 import three、不碰 window/document）。

## 它解决什么

导出/压缩 3D 资产时，"顶点属性用几 bit"通常靠猜或靠肉眼看。本工具把这件事变成**可复算的证书**：

1. **位置 / UV**：逐轴均匀量化到 `bits`，给出解析上界（每轴 `halfStep` 的欧氏范数）**与**全顶点实测精确最坏误差、以及达到该误差的**见证顶点索引**。
2. **法向**：八面体（octahedral）编码到 `bits`/轴；给出网格上的精确最坏/平均角误差与见证顶点，并用 **200,000 条 Fibonacci 球面方向**独立扫描整个码本域验证上界不虚（bits 4…14 上测得的 bound/measured 最大 1.0705，即上界从不下穿真实值）。
3. **最小位深**：给定容差二分求最小 `bits`，并对 `bits-1` 给出**必然超容差的见证**——这就是"最小"的证据，不是猜。

浏览器端（`index.html` + `main.js`）从 CDN importmap 引 three（版本写死 `0.169.0`），把同一份 `src/core.mjs` 跑在页面上：拖位深滑块，误差热力图实时更新；滑块调回 12/8 时，页面会把浏览器算出的最坏相对误差与 node 烘焙的 `data/reference.json` **逐位比对**并显示结论。

## 怎么跑（零依赖，Node ≥ 20）

```bash
node tools/gen-sample.mjs && node bench/verify.mjs   # 生成数据 + 12 条断言，全过 exit 0
node bench/bench.mjs                                  # 冷启动 + 7 次重复 → bench/result.json
python3 -m http.server 4173                           # 打开 http://localhost:4173
```

| 量 | 值 |
| --- | --- |
| 证书全网格（位置+UV+法向，含见证） | 冷启 **20.217 ms**，中位 **5.896 ms**，p95 6.513，relStddev 0.0882 |
| 200k 方向球面 oracle 扫描 | 冷启 31.562 ms，中位 **26.162 ms**，p95 26.409，relStddev 0.0035（**证书比它快 4.44×**） |
| 朴素基线（固定 [-1,1] 位置 + 逐分量法向） | 中位 4.996 ms —— **证书比朴素基线慢 0.847×**，因为它还给出精确最坏值与见证，朴素版只做量化 |

关键数值断言（`node bench/verify.mjs`，12/12 PASS）：

- `A3` 独立 oracle（另一套写法）在 8/10/12/14/16 bit 上复现位置最坏误差，最大相对差 **3.535e-14**。
- `A5` 尺度 **1e-6…1e6**：相对误差散布 **3.248e-13**，最小位深恒为 **9**（尺度不变）。
- `A6` 法向上界在 bits 4/6/8/10/12/14 × 200k 方向上从不下穿真实最坏值（最大 bound/measured **1.0705**）。
- `A8` 等总比特预算对照：八面体 16 bit vs 逐分量 15 bit → 平均 **5.212×**、最坏 **4.593×**。
- `A9/A10` UV 12 bit = **0.3536 texel**@2048，最小位深 12（11 bit = 0.7075 texel 必失败）；位置最小位深 9、法向 8，均带超容差见证。
- `A11` `gen-sample.mjs` 跑两次 `sha256(mesh.json)` 一致（`c24118d9c5d98f75…`）。

## 本轮创新

**B 档。** 台账里没有"顶点属性量化误差证书 / 最小位深"这一条：`gltf-audit-lab` 查的是 GLB 容器完整性，
`depthbudget/depthfence` 是深度缓冲精度，`gradfit-lab` 是梯度认证，都不做属性量化的**最坏误差 + 见证 + 最小位深**。
和现成导出器（gltfpack 等按启发式选位深）的区别是：这里给的是**可复算的精确最坏误差与见证顶点**，并且在
**等总比特预算**下量化了八面体编码相对逐分量编码的收益（5.21×）——不是"建议"，是可以现场跑出来的数字。
"所见即所验"：浏览器拖位深，同一份 `src/core.mjs` 在页面上重算，与 node 烘焙值逐位比对。

## 已知限制（如实披露）

1. **法向上界是保守经验界，不是解析证明**：`boundDeg = 2.2 × 步长(rad)`。在 bits 4…14 的 200k 方向 Fibonacci
   扫描上从不下穿真实最坏值（真实最坏稳定在 2.05–2.10 × 步长），但这只是**在该采样密度下的经验验证**，
   不构成对整球的证明。极密方向（如极点/八面体棱）可能有更坏值。
2. **等预算对照的口径**：八面体 2 轴 × 8 bit = 16 bit，逐分量 3 轴 × 5 bit = 15 bit。
   如果按**每轴位深相同**比（都 8 bit），逐分量在这张网格上反而更好（最坏 0.3403° vs 0.6425°）——因为它多用了 8 bit。
   README 的 5.21× 只在等总预算口径下成立。
3. **位置/UV 误差是逐轴绝对步长定义**：有效于"属性各自落在有限 bbox 内"的常规网格；对于含离群点（outlier）的
   bbox，逐轴均匀量化会被离群点拉大步长，此时应按块/按 primitive 分别量化（本工具未做分块量化）。
4. **示例网格是脚本生成的合成薄带**，不是真实 glTF 资产；数据格式是本仓自有的紧凑 JSON，不是 glTF 二进制。
5. **UV 误差以 2048² 纹理换算成 texel**，不含 wrap/mirror 重复模式与 mip 级别的影响。
6. **没有自动化浏览器测试**（按硬性约束禁用 playwright/puppeteer/chromium）；浏览器路径只验证了
   `python3 -m http.server` 返回 200 + importmap 存在 + 页面与 node 共用同一 `src/core.mjs`。
